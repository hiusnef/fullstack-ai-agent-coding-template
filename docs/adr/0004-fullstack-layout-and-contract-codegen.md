# ADR 0004: Fullstack layout and contract-first type generation

- Status: accepted; backend layout superseded by [ADR 0005](0005-clean-architecture-gradle-multi-module.md)
- Date: 2026-10-28

## Context
The project grows from a backend-only service into a fullstack app: Spring Boot 4 / Java 25 backend and a
Next.js frontend. We need a layout agents can navigate, and a way to keep backend and frontend API shapes in sync.

## Decision
- Backend stays at the repository root (Maven, `src/`); the frontend lives in `frontend/` with pnpm.
- `src/main/resources/openapi/api.yaml` is the single API contract. The frontend generates TypeScript types with
  `openapi-typescript` (`pnpm gen:api`) and calls the API only through an `openapi-fetch` client.
- Generated `schema.d.ts` is gitignored and regenerated by `dev`, `build` and `typecheck`; CI runs `typecheck`.
- The browser calls `/api/*` on the Next.js origin, rewritten to the backend (no CORS).
- Agent rules are scoped by path: `10-java-style` (`src/**/*.java`), `15-frontend` (`frontend/**`).
- Versions at creation: Spring Boot 4.1.2, Next.js 16.4.3, React 19.3, TypeScript 5.9 (openapi-typescript does
  not support TypeScript 7 yet), Vitest 5.

## Alternatives considered
- `backend/` + `frontend/` folders - cleaner separation, but more churn now; can be revisited.
- Hand-written fetch + types - simple at first, drifts silently from the backend.
- Backend generates server interfaces from the contract too (openapi-generator) - stronger guarantee, more build
  complexity; revisit when the API grows.

## Consequences
- Any contract change touches `api.yaml`, the controller and, when used, the frontend in one change.
- Mixed build tooling at the root (`pom.xml`) and in `frontend/` (`package.json`); commands documented in `AGENTS.md`.
- Upgrade to TypeScript 7 waits on openapi-typescript support.
- pnpm 12 refuses unapproved dependency build scripts; decisions live in `frontend/pnpm-workspace.yaml`.
- Surefire loads Mockito as a `-javaagent` (JDK 25 warns on, and will block, dynamic self-attach).
